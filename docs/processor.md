# Processor (Vocabulary) Guide

`src/processor.py` manages per-profile vocabulary markdown files. It reads existing entries, appends new words extracted by the LLM, and tracks frequency and last-seen date.

## What it does

The processor is a thin persistence layer — it doesn't call the LLM or fetch content. Its sole responsibility is managing the vocabulary markdown file at `data/<profile>/vocabulary.md`.

```
Orchestrator
    └── llama_client.extract_vocab() → [{"word": "Haus", "meaning": "house"}]
        └── processor.update_vocab(vocab_list) → appends to data/krystof/vocabulary.md
```

## Vocabulary File Format

Each profile gets its own markdown file:

```markdown
# Vocabulary Database — Profile: krystof

*Auto-generated by LinguaDaily*

| Word | Meaning | Frequency | Last Seen |
| :--- | :--- | :--- | :--- |
| haus | house | 1 | 2026-05-09 |
| sprache | language | 1 | 2026-05-09 |
| groß | big | 1 | 2026-05-09 |
```

- **Word**: Lowercase original word from the article
- **Meaning**: Brief definition in the user's native language (from LLM)
- **Frequency**: Starts at 1, increments on re-encounter
- **Last Seen**: ISO date (`YYYY-MM-DD`) when the word was added

## API

```python
from src.processor import LinguaProcessor

# Create processor for a profile
proc = LinguaProcessor(
    learning_language="de",      # language code (resolves to display name in header)
    profile="krystof",           # determines vocab path: data/krystof/vocabulary.md
)

# Optional: custom vocab path
proc = LinguaProcessor(
    profile="krystof",
    vocab_path="/custom/path/vocab.md",
)

# Update with words from LLM (list of {word, meaning} dicts)
vocab = [{"word": "Haus", "meaning": "house"}, {"word": "Auto", "meaning": "car"}]
proc.update_vocab(vocab)

# Plain strings also work
proc.update_vocab(["Hallo", "Welt"])
```

### `update_vocab(words)`

Appends new words to the markdown file. **Deduplicates** — if a word already exists (case-insensitive), it's skipped. Each new word gets frequency 1 and today's date.

```python
# First call — adds "hello"
proc.update_vocab([{"word": "Hello", "meaning": "greeting"}])

# Second call — skips "hello" (already exists, case-insensitive)
proc.update_vocab([{"word": "hello", "meaning": "salutation"}])

# File contains only one entry for "hello" with frequency 1
```

### `_ensure_vocab_file()`

Creates the markdown file with a header if it doesn't exist. Creates parent directories automatically. No-op if file already exists (preserves existing content).

### `_read_existing_vocab()`

Reads the current vocab file and returns `{word_lower: frequency}` dict. Used internally for deduplication. Skips header rows, separator lines (`|---|`), and empty entries.

## How it fits in the pipeline

1. `Orchestrator.run_lesson()` calls `llama_client.extract_vocab()` → gets list of `{word, meaning}` dicts
2. Orchestrator creates a `LinguaProcessor` for the profile
3. `processor.update_vocab(vocab_list)` appends new words to markdown file

The orchestrator handles all processor lifecycle — you typically don't interact with it directly unless building a custom vocabulary tool.
