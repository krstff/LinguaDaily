# OpenClaw-Lingua: Standalone Migration — Work in Progress

## Goal

Move from an OpenClaw-dependent app to a standalone Python daemon that:
1. Calls local llama.cpp models for translation + tutoring
2. Uses local TTS (already done — OmniVoice via OpenAI-compatible API)
3. Manages Telegram message delivery + interactive LLM chat
4. Schedules lessons locally (replacing OpenClaw cron)

## Assessment (~45% new code, ~55% reuse)

### ✅ Already standalone — keep as-is
- `wikipedia_fetcher.py` — Kiwix/ZIM client
- `news_fetcher.py` — RSS feed fetching
- `fetch_router.py` — content dispatch
- `tts.py` — OmniVoice TTS (already uses OpenAI-compatible API)
- Config/profile system, vocab tracking

### ⚠️ Needs modification
- `orchestrator.py` — currently outputs PAYLOAD_START/END for OpenClaw Agent; needs to become real orchestrator that calls LLM + delivery itself
- `processor.py` — generates LLM instruction strings; translation logic moves to llama_client

### ✅ DONE: `src/llama_client.py` (20 tests, all passing)
Three operations over llama.cpp's OpenAI-compatible `/v1/chat/completions`:
- `translate()` — article translation (temp 0.1)
- `extract_vocab()` — pulls `{word, meaning}` JSON from text
- `tutor_chat()` — interactive Q&A with conversation history (temp 0.7)

**Model resolution chain** (future extensibility for per-task models):
1. Profile task-specific: `llm_translate_model`, `llm_tutor_model`
2. Profile generic: `llm_model`
3. LLM-level defaults: `llm.translate_model`, `llm.tutor_model`
4. Global: `llm.default_model` (e.g. `gemma4-26b`)

### ✅ DONE: `src/telegram_bot.py` (29 tests, all passing)
aiogram 3.x based Telegram bot with two flows:
- **Lesson delivery** — sends translated article text + TTS audio WAV to user's chat
- **Tutor chat** — routes messages to llama_client.tutor_chat() with SQLite conversation history

Features:
- Config-based `telegram_chat_id` mapping in profiles
- `/register <profile>` command for runtime auto-registration
- Commands: `/start`, `/register`, `/history clear`, `/status`
- Conversation history in SQLite (`data/chat_history.db`)
- Telegram 4096-char message limit handling with truncation
- Env var fallback: `TELEGRAM_BOT_TOKEN`

**Config shape needed:**
```json
{
  "telegram": {
    "bot_token": "123456:ABC-DEF..."
  },
  "profiles": {
    "krystof": {
      "telegram_chat_id": 111222333
    }
  }
}
```
